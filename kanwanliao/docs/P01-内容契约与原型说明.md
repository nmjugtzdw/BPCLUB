## 3. 剧透规则（硬门禁）

1. 发帖与评论可标记剧透；默认**折叠**，读者主动展开后才可见正文。
2. 服务端在渲染前必须过滤：`App\Spoiler::publicText()` 是输出前的唯一入口；`summary()` 与 `shareDescription()` 用于列表与分享摘要。
3. 以下位置逐项核对，**任何一处出现被遮挡正文即判定不通过**：帖子标题、列表摘要、作品页、搜索结果、分享 meta、API/HTML 响应、禁用 JS 时的展示。
4. **把原文写进 HTML 再用 CSS / `details` 隐藏不算通过**；必须在服务端就不返回该正文（P03 起在查询/仓储层实现）。
5. 展开动作须由服务端按权限返回，不能靠前端从已下载的正文中"解锁"。
6. P01 阶段首页原型只显示剧透占位提示，不提供展开交互——因为真实展开依赖账号与内容接口（P04）。

## 4. 领域模型与状态

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `users` | `username`、`email`、`password_hash`、`role`、`status` | 只存哈希；角色 `user` / `admin`；状态 `active` / `restricted` / `disabled` |
| `titles` | `name`、`work_type`、`release_year`、`synopsis`、`source_label`、`last_verified_at` | 作品与用户原创内容分离；同名靠 `(name, work_type, release_year)` 区分；删除帖子不删作品 |
| `threads` | `author_id`、`category`、`title`、`body`、`title_id`、`is_spoiler`、`status` | 分类四类；`title_id` 可空；状态 `pending` / `visible` / `hidden` / `deleted` |
| `comments` | `thread_id`、`author_id`、`body`、`is_spoiler`、`status` | 同帖子状态语义 |
| `reports` | `reporter_id`、`target_type`、`target_id`、`reason`、`status`、`handled_by` | 举报闭环与处置留痕 |
| `admin_audit_logs` | `actor_id`、`action`、`target_type`、`target_id`、`context` | 记录操作者与对象，**不记录密码** |

- **隐藏 / 删除语义**：一律用 `status` 表达，业务数据不物理删除；受限账号、待审核、已隐藏 / 已删除内容在各入口行为一致，不得从列表、搜索、作品页或分享预览泄露。
- **权限**：未登录只能读已公开内容；作者本人可编辑自己的内容，非本人不得编辑；普通用户不可访问管理界面或管理接口；管理员操作全部留痕。待审核内容的可见性在 P03 实现前明确并测试。
- **时间**：全部 `DATETIME` 存 UTC，连接执行 `SET time_zone = '+00:00'`，应用层固定 UTC；界面显示按北京时间换算，不依赖运行环境时区。
- **404 / 空状态 / 分页**：不存在的资源 404；空列表、空搜索结果、未收录作品都有明确提示；分页参数须校验并在 P03 定义默认页大小。
- **种子数据**：`database/seeds/demo.sql` 只含明确标注「演示虚构」的作品占位，**不插入任何用户、帖子、评论、评分或活跃度**；真实内容由用户 / 编辑提供，且仅允许在隔离开发库手动执行。
