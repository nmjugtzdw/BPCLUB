# 影视论坛：安全与运维手册（P06）

> 适用范围：「看完聊」影视讨论论坛（PHP 8.2 + MySQL，部署于宝塔 Nginx）。
> 本文记录已实施的安全措施、验证结果、运维操作与上线前仍需业主确认的事项。
> 文中所有结论都对应真实执行过的命令；未执行的部分会明确写「未验证」。

## 1. 账号与权限模型

| 项目 | 实施方式 |
|---|---|
| 密码存储 | `password_hash(PASSWORD_DEFAULT)`（bcrypt），仅存哈希，任何页面与日志都不返回密码 |
| 密码强度 | 至少 8 位、必须含字母与数字、最长 72 字节（bcrypt 上限，超出显式拒绝而不是静默截断） |
| 登录标识 | 用户名或邮箱 |
| 会话内容 | 只存用户 id 与一个 CSRF 令牌；角色与状态**每次请求从库里读**，降权、限制、停用立即生效 |
| 会话 Cookie | `HttpOnly` + `Secure`（HTTPS 下）+ `SameSite=Lax` + `use_strict_mode`（拒绝未签发的会话 id） |
| 登录/退出 | 均更换会话 id，防止会话固定 |
| 停用账号 | 登录被拒（403）；已登录的会话在下次请求即被清除 |
| 角色 | 只有 `user` / `admin`；没有任何路由接受客户端传入的角色或用户 id 作为身份 |

权限判定全部在服务端控制器：

- 未登录访问 `/publish`、`/admin` → 303 跳 `/login`
- 已登录非管理员访问 `/admin` → **403**
- 管理员不能限制或停用自己的账号（防自锁）
- 只有 `visible` 的帖子可被评论，其余一律 404（不确认被处置内容是否存在）

## 2. 输入校验与输出转义

- 所有表单输入经 `App\Validation` 校验：用户名 2–20 字（中文/字母/数字/下划线）、邮箱格式、密码强度、标题 2–150 字、正文 1–20000 字、评论 1–2000 字、举报原因 2–500 字。
- 输出一律 `htmlspecialchars(ENT_QUOTES | ENT_SUBSTITUTE)`（`View::e()`），视图里没有裸输出。
- 非 UTF-8 的畸形字节会被丢弃而不是静默变空，随后由校验给出提示。
- 分页、排序、分类均为白名单或强制整数，SQL 全部 PDO 预处理 + 参数绑定（`ATTR_EMULATE_PREPARES=false`）。
- 重定向只接受站内相对路径（拒绝 `//` 与绝对 URL），避免开放重定向。
- 写操作一律 **303 See Other**，刷新不会重复提交。

## 3. CSRF 与滥用控制

- 每个写操作（注册、登录、退出、发帖、评论、举报、全部管理操作）都校验会话内 CSRF 令牌，`hash_equals` 比较；失败返回 422 且**不执行任何写库**。
- 固定窗口限流（`rate_limits` 表，键为 `地址|账号` 的 SHA-256，不存明文 IP）：

| 动作 | 上限 | 窗口 |
|---|---|---|
| 登录（按来源地址） | 20 次 | 10 分钟 |
| 登录（按账号） | 10 次 | 15 分钟 |
| 注册（按来源地址） | 5 次 | 1 小时 |
| 发帖（按账号） | 10 次 | 1 小时 |
| 评论（按账号） | 30 次 | 1 小时 |
| 举报（按账号） | 10 次 | 1 小时 |

超限返回 **429** 并写一条 `rate_limited` 日志。线上实测：连续注册触发 429。

## 4. 内容可见性与审核策略（明确定义）

**2026-11-14 03:15 起改为「全部先审后发」**：任何账号发布的新帖与新评论都先进 `pending`，管理员在 `/admin` 放行后才公开。此前「`active` 账号直接 `visible`」的规则已废弃。

| 账号状态 | 发帖/评论状态 | 公开可见性 |
|---|---|---|
| `active` | `pending` | 需管理员在 `/admin` 通过后才公开 |
| `restricted` | `pending` | 需管理员在 `/admin` 通过后才公开 |
| `disabled` | 不能登录 | — |

处置状态：`visible`（公开）、`hidden`（隐藏，各入口一致不可见）、`deleted`（删除标记，不物理删除）、`pending`（待审）。

**运维必读**：因为不再有「自动公开」路径，站点必须始终存在至少一个可登录的 `admin` 账号，否则所有新内容会永久停留在待审。当前线上管理账号为 `dl20052006`（id 8）。账号丢失或需要新增管理员时，按 §11 用一条 SQL 授权。

选择理由：内容全部经过人工确认再公开，避免演示/公测阶段出现未审内容；代价是新用户发帖后看不到自己的内容，需在提示语里明确「需要管理员看过之后才会公开」（界面文案已同步）。

## 5. 剧透规则的服务端落实

剧透不是 CSS 折叠，而是**查询层就不返回正文**：

- 列表、作品页、搜索结果、用户主页：剧透帖标题替换为「含剧透的讨论」，正文列在 SQL 里直接返回 `NULL`。
- 搜索：剧透帖不参与标题与正文匹配，避免搜索结果成为「猜原文」的旁路。
- 详情页：未点「我确认，展开剧透」前，`body` 在 SQL 层就是 `NULL`。
- 分享摘要（`og:description`、`meta description`）：剧透帖只输出提示文本。
- 无 JS 场景：折叠不依赖 JS，默认输出即为折叠态。

线上实测：默认页面 0 次正文出现；`?reveal=1` 后出现；首页/搜索/作品页均 0 次泄露。

## 6. 安全响应头

`Response::send()` 统一输出：

```
Content-Security-Policy: default-src 'self'; base-uri 'none'; form-action 'self';
  frame-ancestors 'none'; img-src 'self' data:; style-src 'self'; script-src 'self';
  object-src 'none'; connect-src 'self'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: same-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
Strict-Transport-Security: max-age=31536000; includeSubDomains   （仅 HTTPS）
```

页面没有内联脚本与内联样式，严格 CSP 不影响渲染；线上实测 **0 条 CSP 违规**。
注：Nginx 站点配置本身也发了一条 `Strict-Transport-Security`（无 `includeSubDomains`），浏览器取第一条，不构成风险；如需消除重复可在站点配置里去掉其一。

## 7. 日志与审计

- 应用日志 `storage/logs/app.log`：UTC 时间戳，`pass/secret/token/cookie/authorization/credential` 等键自动脱敏为 `[redacted]`。
- 管理操作审计表 `admin_audit_logs`：操作者、动作、对象类型与 id、上下文（JSON）、UTC 时间。上下文同样脱敏，不写密码与令牌。
- 已实测：隐藏帖子、处置账号、驳回/处理举报都会各写一条审计；管理员自锁被拒时不写库。

## 8. 备份与恢复

### 8.1 备份

```bash
cd /www/wwwroot/kwl.zzzmxxkj.com
sudo -u www bash scripts/backup.sh
```

- 默认只允许对库名以 `_dev` / `_test` 结尾的库执行；对其它库需显式 `--allow-prod`。
- `--single-transaction` 一致性快照，不锁表；`--no-tablespaces` 让低权限账号也能导出。
- 产物 `storage/backups/<库名>-<UTC时间>.sql.gz`，目录 `700`、文件 `600`，已加入 `.gitignore`。
- 空文件或 `gzip -t` 失败会被判为失败并删除产物，不留坏备份。
- 默认保留最近 14 份（`KEEP=14` 可覆盖）。

实测（2026-11-14 01:46 UTC）：`kanwanliao_dev-20261113-174651.sql.gz`，4471 字节，8 张表，SHA256 `2d992872…56e4`。

### 8.2 恢复

```bash
sudo -u www bash scripts/restore.sh <备份文件.sql.gz> --target=<库名> --yes
```

- 目标库必须存在、必须以 `_dev`/`_test` 结尾、且不能等于当前运行库。
- 必须显式 `--yes`；脚本先做 `gzip -t` 校验再导入。
- 低权限账号无权建库（实测 ERROR 1044），因此**脚本不建库、不提权**；新库由管理员创建并授权后使用。

### 8.3 恢复演练（已执行）

```bash
sudo -u www bash scripts/backup-drill.sh
```

做法：导出数据 → 同库建 `CREATE TABLE ... LIKE` 克隆表（不复制外键）→ 表名替换后导入 → 逐表比对行数 → 清理克隆表。

实测结果（8 张表全部一致）：

| 表 | 原表 | 恢复 | 结果 |
|---|---|---|---|
| users | 5 | 5 | 一致 |
| titles | 5 | 5 | 一致 |
| threads | 11 | 11 | 一致 |
| comments | 5 | 5 | 一致 |
| reports | 1 | 1 | 一致 |
| admin_audit_logs | 2 | 2 | 一致 |
| rate_limits | 6 | 6 | 一致 |
| schema_migrations | 2 | 2 | 一致 |

演练后确认库中无 `bkdrill_%` 残留表。

**未验证（须说明）**：没有做「新建独立库再恢复」的演练，因为本项目账号无建库权限、共享实例的管理员凭据不由本项目保存。真正的新库恢复需管理员建库授权后执行。

**浏览器兼容未验证**：以上检查只在 Chrome（headless）中执行，Firefox / Safari / 微信内置浏览器未实测；上线前建议补齐这三项人工走查。

| 低于 WCAG AA | **0** |
| 横向溢出 | **0** |
| 无标签表单控件 | **0** |
| CSP 违规 | **0** |
| 键盘 Tab 12 步内焦点不可见 | **0** |

工具本身有两处必须保留的保护，否则会得出假通过：

1. 每次导航后断言 `location.host` 确实为目标站点——Chrome 冷启动失败时会渲染 `chrome-error://` 错误页，错误页同样能跑 DOM 统计，会产出「0 溢出 0 违规」的假结果。
2. 代理是可选项（`KWL_PROXY`）。本机代理未监听时若仍强制走代理，所有页面都会变成错误页。

## 11. 创建管理员与测试数据清理

站内**没有注册即管理员的入口**，也没有隐藏的默认管理员账号。需要一个管理员时，先正常注册一个账号，再由能连库的人执行一次授权：

```sql
-- 在隔离库里执行；把 '你的用户名' 换成实际账号
UPDATE users SET role = 'admin', updated_at = UTC_TIMESTAMP() WHERE username = '你的用户名';
```

注意：

- 角色每次请求从库里读，改完刷新页面即生效，无需重启。
- 管理员不能限制或停用自己（防止把自己锁在门外）。
- 验收或压测产生的账号、帖子、评论、举报、审计记录、限流计数应及时清理，避免留下已知密码的账号。清理顺序必须遵守外键方向：

```sql
DELETE FROM admin_audit_logs WHERE actor_id IN (…);
DELETE FROM comments        WHERE author_id IN (…);
DELETE FROM reports         WHERE reporter_id IN (…);
DELETE FROM threads         WHERE author_id IN (…);
DELETE FROM users           WHERE id IN (…);
DELETE FROM rate_limits;   -- 限流计数可整体清空
```

2026-11-14 01:45 的验收数据（2 个测试账号、2 篇帖子、1 条评论、2 条举报、3 条审计）已按上述顺序清理，站点回到演示种子状态：3 个不可登录的示例作者、9 篇帖子（含 1 篇 hidden、1 篇 pending）、4 条评论。

## 12. 日常运维命令

```bash
# 健康检查
curl -s https://kwl.zzzmxxkj.com/health

# 迁移状态 / 应用 / 回滚最后一个版本
sudo -u www /www/server/php/82/bin/php scripts/migrate.php status
sudo -u www /www/server/php/82/bin/php scripts/migrate.php up
sudo -u www /www/server/php/82/bin/php scripts/migrate.php down

# 备份 / 演练
sudo -u www bash scripts/backup.sh
sudo -u www bash scripts/backup-drill.sh

# 代码发布（本机工程根执行）
bash kanwanliao/scripts/deploy.sh
```

排障要点：

- 服务器 CLI 默认 PHP 是 7.0.33，本项目必须用 `/www/server/php/82/bin/php`。
- 服务器 `.env` 的密码键名是 `DB_PASS`（不是 `DB_PASSWORD`）；写错会让 `mysql` 转交互式索要密码，SSH 命令静默卡死。
- 千万不要用 `systemctl reload nginx`（宝塔 nginx 不走 systemd），用 `/www/server/nginx/sbin/nginx -s reload`。
- `/title/1` 返回 404 是正常的：作品 id 实际从 2 开始。
