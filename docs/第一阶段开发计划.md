## 一、目标与边界

建设中文综合福利情报论坛，覆盖 AI 工具、正版软件、游戏、生活优惠、云服务及日常交流。参考 NodeSeek 的信息密度、导航、双栏布局和简洁交互，但使用原创品牌、视觉、组件及文案，不复制受保护素材。

第一阶段仅实现响应式前端和类型安全的模拟数据：**不连接真实数据库、不实现真实认证，不声称演示交互已保存到服务器**。数据访问通过 Repository 接口隔离，为后续 PostgreSQL + Drizzle 留出接入边界；本阶段不提前引入数据库。

## 二、技术与约束

- Nuxt 3、Vue 3 Composition API、TypeScript 严格模式。
- 与 Nuxt 3 兼容的稳定版 Tailwind CSS；Lucide Icons；ESLint；Vitest；npm。
- 仅在跨页面确有共享状态需求时引入 Pinia；采用模块化单体，不引入微服务。
- 语义化 HTML、键盘可操作、可见焦点、表单基础校验、图片替代文本；不使用 `any` 绕过检查。
- 固定模拟数据，不使用导致服务端与客户端渲染不一致的随机值；状态按 UTC 时间计算，并避免首屏水合不一致。
- 视觉以 1200px 最大容器、约 60px 顶栏、约 860px 主栏和约 300px 侧栏为目标；响应式布局下按实际空间调整。
- 浅色基准：背景 `#F7F8FA`、卡片 `#FFFFFF`、正文 `#1F2937`、辅助文字 `#6B7280`、边框 `#E5E7EB`、品牌蓝 `#2563EB`、正常 `#16A34A`、警告 `#F59E0B`、错误 `#DC2626`；同时支持深色模式。避免大面积渐变、玻璃拟态、夸张阴影和过度圆角。

## 四、领域模型与数据

设计用户、分类、帖子、评论、福利记录等类型；帖子区分普通讨论与福利分享。福利记录包括官方领取链接、开始/截止时间、适用地区、领取条件及核验状态（待核验、已验证、已过期、已失效）。过期显示基于 UTC 时间，数据中的人工核验状态与计算出的展示状态应明确区分。

固定数据目标：至少 30 条中文帖子、8 个用户、6 个分类、40 条评论、15 条福利记录；各页面复用同一数据源并确保引用有效。有效/失效反馈仅修改本地演示状态，界面明确说明刷新后的状态及未提交服务器的事实。

## 五、分轮实施

### 第一轮：工程骨架与首页（用户已授权范围）

1. 检查现有目录、项目规则、运行环境及 Git 状态，避免覆盖已有内容。
2. 初始化 Nuxt 工程与目录；配置严格 TypeScript、Tailwind、ESLint 和必要脚本。
3. 建立设计变量、浅/深色基础、响应式全站 Header、Sidebar、Footer。
4. 建立领域类型、Repository 接口及固定 Mock 数据；实现首页帖子列表和必要的可操作交互。
5. 创建并持续更新 `TASKS.md`，记载已完成项、待办、实际验证结果。
6. 安装依赖，尝试启动开发服务器并验证；运行 `npm run typecheck` 与 `npm run build`。受环境限制时如实记录错误与未运行项目，不虚报成功。
7. 第一轮结束即停止，报告文件、命令、证据和下一轮建议，等待用户确认。

**第一轮验收**：工程可安装、首页可运行且布局响应式；模拟数据达到约定数量并可复用；类型检查和构建通过，或对环境阻塞提供可复现的真实错误。尚未开发的入口不得假装可用，应清晰标注或不呈现为可操作入口。

### 第二轮：分类、详情与发帖（须经用户确认）

- 分类页 `/category/[slug]`：分类筛选、帖子列表与空状态。
- 详情页 `/post/[id]`：正文、福利信息、UTC 展示状态、评论、本地反馈。
- 发帖页 `/new`：讨论/福利表单、基础校验、演示状态提示；不虚构服务端保存。
- 完成对应列表、详情、编辑器、评论、福利与通用状态组件；添加针对性测试。

### 第三轮：其余页面（须经用户确认）

- 搜索 `/search`、登录 `/login`、注册 `/register`、用户主页 `/user/[username]`、福利日历 `/calendar`、管理后台 `/admin`。
- 搜索和日历复用 Mock 数据；认证与管理操作明确标记演示性质，不伪装真实权限或持久化。
- 补齐移动导航、用户资料、搜索、分页、对话框等所需组件与键盘交互。

### 第四轮：测试、文档与收口（须经用户确认）

- 为关键组件及 UTC 状态等工具函数编写单元测试，覆盖边界、空状态及演示交互。
- 运行 `npm run typecheck`、`npm run lint`、`npm run test`、`npm run build`；记录实际结果和剩余限制。
- 完成 `README.md`、`UI-SPEC.md`、`TASKS.md`；人工检查桌面与移动布局、深浅模式及主要键盘路径。
- 按用户确认的范围提交本地 Git；推送远端前等待明确指示。
