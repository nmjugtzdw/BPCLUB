# 影视讨论论坛：项目白皮书与总体方案

> 2026-11-13 · 讨论形成的开发基线；产品名称暂定「影视讨论论坛」，域名、商标、视觉品牌待用户确认。本文取代 V1/V2/V3 的产品方向，但不视为用户授权部署、覆盖已有代码或开放注册。

## 1. 项目定位

建设一个讨论电影与电视剧的中文论坛：看完聊感受、讨论剧情、寻求推荐。首页以帖子列表为中心，参考 NodeSeek 的紧凑布局与互动思路，品牌、文案、组件和代码自主设计；不复制其专有素材。

目标人群：喜欢看电影或电视剧、希望轻松聊剧情和推荐作品的普通观众。首要价值是围绕一部作品找到真实讨论，不追求影片数量或虚构活跃度。首批话题由真实用户/编辑提供，禁止编造用户、评论或评价；测试内容应明确标注演示。

## 2. 参考项目与授权边界

产品思路参考 [ScreenJournal](https://github.com/mtlynch/screenjournal) 的影视资料和影评组织方式，以及 [Films with Friends](https://github.com/gabtorre/films-with-friends) 的影评回复交互。不是采用其代码或直接部署：前者已归档且采用 AGPL-3.0-or-later；后者许可证及独立部署条件尚未确认。**剧透功能是本项目需求，不能声称上述项目已经实现。** 若将来拟引入代码、素材或数据，须先单独核查授权和依赖，未经确认不复制。

## 3. 产品范围

### 首版目标

- 首页：最新帖子、可解释的热门排序，电影、电视剧、求推荐、闲聊四类入口。
- 作品：电影/电视剧基础资料页，关联影评与讨论；支持搜索、同名作品区分、未收录提示。
- 互动：注册、登录、退出；发帖、详情、评论；可选关联作品；影评不强制打分。
- 剧透：发帖及评论可标记剧透；列表、标题与摘要不暴露剧透正文；剧透内容默认折叠，用户主动展开；服务端返回与公开预览、搜索摘要、分享摘要、无 JS 展示均不得泄露被遮挡内容。
- 管理：用户举报、审核处置、管理员认证和授权、最小操作日志。未审核内容的可见性需在实现前明确并测试。
- 响应式页面、可访问的键盘操作、浅深色主题。

### 不做

不提供影片或音频托管、在线播放、盗版资源下载/链接；不做自动抓取影评和海报、大型影片库、会员付费、复杂推荐系统、私信、积分等级、移动 App。图片上传首版默认不开放，文字与自有设计为主；如需开放须另审版权、安全、成本。前述范围经用户后续明确变更时再调整。

## 4. 页面与关键流程

| 页面 | 建议路径 | 功能 |
|---|---|---|
| 首页 | `/` | 最新/热门、分类、帖子列表、登录与发布入口 |
| 分类 | `/category/{slug}` | 按电影、电视剧、求推荐、闲聊查看帖子 |
| 作品 | `/title/{id}` | 名称、年份、类型、简介、相关影评与讨论 |
| 帖子 | `/thread/{id}` | 正文、作品关联、评论、剧透与举报 |
| 发布 | `/publish` | 分类、标题、正文、可选作品和剧透标记 |
| 搜索 | `/search` | 搜索作品与帖子，正确处理空结果 |
| 账号 | `/login`、`/register`、`/user/{id}` | 登录注册与用户公开资料 |
| 管理 | `/admin` | 管理员审核、举报及操作记录 |

核心闭环：访问列表 → 搜索或打开作品 → 阅读讨论 → 登录 → 发帖/评论 → 管理员处置举报。不存在的资源返回 404；非本人不得编辑他人内容；受限账号和已删除/隐藏内容不得通过其他入口泄露。

## 5. UI 与交互

简洁、紧凑、轻量：桌面最大宽度约 1200px，帖子主栏与约 300px 侧栏，移动端单栏；可在实际设计中调整，避免小屏横向溢出。视觉基准背景 `#F7F8FA`、卡片白色、正文 `#1F2937`、辅助 `#6B7280`、边框 `#E5E7EB`、链接/强调蓝 `#2563EB`。深色主题须有可读对比度。无巨幅 Banner、玻璃拟态或夸张阴影。

语义化 HTML，Tab 键可达、可见焦点、表单错误关联、图像有替代文本；移动端和桌面均实际检查。禁用的功能明确未开放，不设置无意义按钮。

## 6. 技术方向及未决事项

**建议**沿用用户 V3 文档中提出的 PHP 8.x + PDO + MySQL/MariaDB + Nginx/PHP-FPM、原生 HTML/CSS/JS、模块化单体；该文档原为另一产品方向，用户本轮只确认影视产品参考，并未逐项确认技术栈，故该方案**待用户确认**，不可当成新的既定决定。无需为参考项目切换到 Go、Firebase 或 TMDB。实际 PHP、数据库版本、扩展和部署方式须只读核实，不能为了新项目升级共享服务。

若采用 PHP/MySQL：`public/` 为唯一 Web 根目录；配置、日志、测试、迁移与备份位于根目录之外；PDO 参数化，版本化迁移及对应回滚说明，utf8mb4，显式约定 UTC。应用、数据库、账号、日志和备份隔离。不得直接执行旧静态预览同步脚本部署新系统。

## 7. 领域模型（候选，不是已创建表）

- `users`：账号、密码哈希、状态、创建时间；不保存明文密码。
- `titles`：电影/电视剧、名称、年份、简介、数据来源、最后核对时间；同名作品依作品类型、年份等区分。
- `threads`：作者、分类、标题、正文、可选 title_id、剧透标记、审核状态、时间。
- `comments`：帖子、作者、正文、剧透标记、审核状态、时间。
- `reports`：举报对象、原因、状态、处理结果；`admin_audit_logs`：操作者、动作、对象、时间与必要上下文。

表结构在数据库设计阶段确定主键、外键、索引、唯一约束、删除/隐藏语义和迁移回滚。作品与帖子分离，删除帖子不删除作品；作品数据与用户原创评价分开管理。

## 8. 安全与内容边界

密码使用可靠密码哈希及随机盐；会话使用 HTTPS、安全 Cookie、会话轮换；敏感操作进行 CSRF 防护，服务端始终验证权限与输入。输出按上下文转义，防 XSS；登录、注册、发布、评论、举报具备速率限制和滥用控制；错误不泄露凭据或堆栈。链接按允许协议处理并避免不安全重定向；后台与审计日志限制访问。任何举报、审核、删除均可追溯，尊重隐私及数据最小化。

不把电影台词、剧照、海报等视为可自由复制；版权、用户协议、隐私、账号与跟帖管理、举报及适用资质由上线前按实际业务核查，不以本文代替法律意见。用户生成内容的审核和投诉处理是正式开放的前置条件。

## 9. 运营与成功判断

先用真实观影感受组织少量话题、邀请真实用户交流，不购买或伪造互动。观察：有人愿意发第一帖、帖子是否获得真实回复、用户是否回来继续讨论、求推荐是否能得到有用回答。指标仅用于观察，不承诺流量或收入。初期允许不做复杂评分排行，以社区体验为主。
